Dynamic Device File creation:
* In linux, we can create device file dynamically (on-demand), need not have to create the device file manually under
/dev directory.
* User level program such as user level daemon 'udevd' can populate the /dev directory with device files dynamically.
NOTE: The 'udevd' runs in background looks for uevents, analyze it and populate /dev directory. It actively listens to
uevents generated by hotplug events or kernel modules. When udev receives the uevents, it scans the subdirectories of
/sys/class looking for the 'dev' files to create the device files.
* For each 'dev' file, which represents a combination of major and minor number for a device, the udev program creates
a corresponding device file in /dev directory. 
udev --analyze--> uevents --read--> dev files --generate--> device files.

Udev:
* Relies on device information  being exported to user space through sysfs meaning that kernel module now should export 
your device information like device filename, major and minor number to sysfs.
* Two reasons for uevents generation:
i. When device drivers take the help of kernel API to trigger dynamic creation of device files.
ii.When a hot plug event occurs like USB plugged into the system.
* All that a driver needs to do, for udev to work properly with it, is ensure that any minor and major numbers assigned 
to a device controlled by the driver are exported to userspace through sysfs.
* The driver exports all the information regarding the device file name, major and minor number to sysfs by calling the 
function device_create().
* udev looks for a file called 'dev' under /sys/class tree of sysfs, to determine what the major and minor number is 
assigned to a specific device.
device plugged in --system_detects--> device_driver --looks_for_a_way_to_communicate --generate_uevents--> udev analyses

class_create(): 
* Create a directory in sysfs: /sys/class/<our_class_name>
device_create(): 
* This functions creates a subdirectory under /sys/class/<your_class_name> with your device name.
* This function also populates sysfs entry with a dev file which consists of the major and minor number, separated by a :
character

Device/kernel module

Create and register a class with sysfs:

struct  class* class_create(struct module *owner, const char *name);
struct module *owner -> pointer to the module that is to own this struct class
const char *name -> string for the name of this class
This creates a class directory under /sys/class/our_created_class_name

The below method populates the sysfs class created in the previous step with device numbers and device names.
struct device* device_create(struct class* class, struct device* parent, dev_t devt, void *drvdata, const char *fmt, ...);
parameters 1 : pointer to the struct class that this device should be registered to.
2 : pointer to the parent struct device of this new device.
3 : dev_t for the char device to be added.
4 : data to be added to the device for callbacks
5 : string for the device name.
