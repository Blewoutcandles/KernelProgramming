Dynamically register a range of char devices numbers 
int alloc_chrdev_region(dev_t *dev, unsigned int baseminor, unsigned int count, const char* name);
dev_t *dev              -> The device number will be updated here.
unsigned int baseminor  -> first of the requested range of the minor numbers like 0 (first minor number)
unsigned int count      -> number of minor numbers required if count = 7 and first minor is 0 
                           then devno:0 -> devno:6 will be created
const char* name        -> name of the associated device or driver

Datatypes:
dev_t -> type alias of u32, out of 32, 12 bits -> major number and 20 bits -> minor numbers.
Macros to obtain the major number: MAJOR(device_number)
Macros to obtain the minor number: MINOR(device_number)
These macros available in linux/kdev_t.h
To convert the major and minor numbers into device numbers: MKDEV(int major, int minor).

cdev_add:
void cdev_init(struct cdev *cdev, const struct file_operations *fops); -> implemented in fs/char_dev.c
struct cdev -> structure to initialize 
struct file_operations -> file operations for this device. We are required to implement 
                          system call handlers like(read,write,seek etc)

struct cdev{
    struct kobject kobj;
    struct module *owner; 
    const struct file_operations *ops; 
    struct list_head list;
    dev_t dev;
    unsigned int count;
} __randomize_layout;

i. const struct file_operations *ops -> pointer to file operation structure of the driver.
ii.struct module* owner -> pointer to the module that owns this structure, usually initialized to THIS_MODULE, this pointer
used to prevent the module from being unloaded while the structure is in use.

THIS_MODULE:
* A macro which resolves into pointer to struct module variable which corresponds to our current module.
* you can find this in linux/export.h
extern struct module (&__this_module)
#define THIS_MODULE (&__this_module)
