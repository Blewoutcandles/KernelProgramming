Kernel build ways:
1. Statically link against the kernel image
2. Dynamically loadable

Dynamically loadable:
2 types:
1. In tree module: (internal to the linux source tree)
2. Out tree module: (external to the linux source tree) - This method taints the kernel, issues a warning saying
out of the tree module has been loaded, we can safely ignore this.

Building a kernel module  (out of tree):
kbuild- the build system used by the linux kernel. 
*Must use this system to stay compatible with changes in the build 
*infrastructure and to pick up the right flags to GCC.
*Must have a prebuilt kernel source that contains the configurations and header files used in the build
*Thus ensuring if the developer make some changes to the kernel configuration, our custom driver will rebuilt with the 
correct kernel configuration.
*Why prebuilt kernel source required?   Modules are linked against the  object files it found in the kernel, 
we cannot compile against one linux version and load into the system which runs different kernel version even loading 
is successful there might be symbol lookup error. Keep a kernel source in your system and build kernel against it.

Two ways to obtain the prebuilt kernel version:
1. Download linux kernel from distributor and built by yourself 
2. Install the Linux-headers of the target linux kernel

cmd to build external modules:
make -C <path to linux kernel tree> M=<path to your module> [target]

syntax explanation: 
make -> command that trigger the top level make file and redirects to the local makefile
-C compiler switch to trigger the top level makefile
M  to redirect the build flow to the local makefile

Linux Source tree: Top level make file ---> Local MakeFile : our working directory where external modules are built.

General syntax: make -C $KDIR M=$PWD [Targets]
-C $KDIR -> The directory where the kernel source is located. Make initially points to this specific directory and will 
change back when finished executing.
M=$PWD -> Informs the kbuild that an external module is being built. Value to M is the absolute path of the directory 
where the external module (kbuild file) is located.
[Targest] :
1. modules -> Default target for external modules. Same functionality as if no target was specified.
2. modules_install -> Install the external modules. The default location is /lib/modules/<kernel_release>/extra/, but a
prefix may be added with INSTALL_MOD_PATH
3. clean -> Remove all the generated files in the module directory only.
4. help -> List the available targets for external modules.

Kbuild rules (used by top level makefile):
* Compiler switches
* Dependency list
* Version string

Building a kernel module  (In tree):
* Instead of building our modules externally, we can actually build it along with our kernel modules.
* If you want to list your kernle module selection in kernel menuconfig, then create and use a Kconfig file.

Steps to add in-tree module to kernel menu configuration:
1. Create a folder in drivers/char/my_c_dev

2. copy main.C or helloworld.c whatever the module name is.
takeoff@takeoff-ASUS-TUF-Gaming-F15-FX506LH-FX566LH:~/code/Rspi_linux/drivers/char$ mkdir my_c_dev
takeoff@takeoff-ASUS-TUF-Gaming-F15-FX506LH-FX566LH:~/code/Rspi_linux/drivers/char$ cd my_c_dev/
takeoff@takeoff-ASUS-TUF-Gaming-F15-FX506LH-FX566LH:~/code/Rspi_linux/drivers/char/my_c_dev$ touch Kconfig
takeoff@takeoff-ASUS-TUF-Gaming-F15-FX506LH-FX566LH:~/code/Rspi_linux/drivers/char/my_c_dev$ cp ../../../../MyModules/001Helloworld.c .
takeoff@takeoff-ASUS-TUF-Gaming-F15-FX506LH-FX566LH:~/code/Rspi_linux/drivers/char/my_c_dev$ ls
001Helloworld.c  Kconfig

3. create a Kconfig file and add the below contents:
menu "my_custom_modules"
  config CUSTOM_HELLOWORLD
    tristate "hello world module support"
    default m
endmenu
Exp:When configuring the kernel we will have options to actually modify the kernel settings.
* Syntax should start with 'menu' and ends with 'endmenu'
* CUSTOM_HELLOWORLD -> kernel identifier, config name. The config keyword preceeds the configname or 
the kernel identifier. config name should be in upper case. This config name will later appear in .config file.
The kernel module identifies this module using its kernel identifier or config name. This module can either be 
included or excluded(selected or deselected during the build process). This will be determined by state of the modules. 
* tristate -> there are 3 states to the modules. m, y or n. tristate will be followed by description and the 
state of the module can be determined using default keyword with options of m, y or n.
* Every module included here will have their own config name.

4. Add the local Kconfig entry to upper level Kconfig
* Navigate to the immediate parent folder and add the  current Kconfig to the parent Kconfig:
source your new directory my_c_dev
eg: add 'source "drivers/char/my_c_dev/"' to end of the parent Kconfig file.

5. create a local Makefile and add this content:
obj-$(CONFIG_CUSTOM_MODULES) += 001Helloworld.o
* To determine the module state we have give $(config name given in the Kconfig file see step 3 and should be preceeded 
by 'CONFIG_')
6. add obj-<config_item> +=  <module>.o in to Makefile. Refer above example command.
7. add local level makefile to higher level makefile.
Navigate to the immediate parent folder makefile, and add 
obj-y += my_c_dev/
-y to make sure our module is always included in the build process, also selecting folders don't have config items.
We just want our custom folder to be always included.
+= my_c_dev/ -> provide them with the path to include the local makefile
If the above obj-y += my_c_dev/ is missed then the parent makefile dont know our my_c_dev folder exist and it 
needs to get compiled. Once this staement is added the parent make file will make jump to our local make file 
to build our 001Helloworld module.
Dont confuse with config_name in Kconfig that is kernel module selection or deselection.

* Once this is done we can go ahead with menuconfig with cmd inside raspi_linux source:
make ARCH=arm64 menuconfig

* This will create a .config file inside the Rspi_linux directory. There you could find the Module as 
#my custom modules  -> see Kconfig file in drivers/char/my_c_dev
CONFIG_CUSTOM_MODULES=m
